## 설정·명령어 기록

설치 대상은 `/opt/agent-app`이며 경로에 사용자 홈의 상위 디렉터리 접근 문제가 생기지 않도록 구성했다. 계정과 권한은 다음과 같다.

| 항목 | 소유자:그룹 | 모드·접근 정책 |
| --- | --- | --- |
| agent-common | agent-admin, agent-dev, agent-test | 업로드 공동 작업 |
| agent-core | agent-admin, agent-dev | 키·운영 로그 접근 |
| `/opt/agent-app` | root:agent-common | 2750, 일반 계정 경로 탐색 |
| `upload_files` | agent-admin:agent-common | 2770 + 기본 ACL, 공동 읽기·쓰기 |
| `api_keys` | agent-admin:agent-core | 2770 + 기본 ACL, test 접근 차단 |
| `/var/log/agent-app` | agent-admin:agent-core | 2770 + 기본 ACL, test 접근 차단 |
| `api_keys/t_secret.key` | agent-admin:agent-core | 0660, 내용 `agent_api_key_test` 1줄 |
| `bin/monitor.sh` | agent-dev:agent-core | 0750, admin 실행 가능 |
| 아카이브 디렉터리 | agent-admin:agent-core | 2770 + 기본 ACL |

주요 명령은 `id`, `ls -ld`, `getfacl`, `stat`, `sshd -T`, `ss -ltnp`, `ufw status verbose`, `crontab -u agent-admin -l`이다. `scripts/collect-evidence.sh`가 이 명령의 결과와 실제 사용자별 접근 허용·차단 결과를 한 파일로 수집한다. 새 공유 파일을 agent-dev가 기본 umask 0022로 만들어도 admin·test가 쓸 수 있는지도 검사한다.

환경변수는 `AGENT_HOME=/opt/agent-app`, `AGENT_PORT=15034`, `AGENT_UPLOAD_DIR=/opt/agent-app/upload_files`, `AGENT_KEY_PATH=/opt/agent-app/api_keys/t_secret.key`, `AGENT_LOG_DIR=/var/log/agent-app`이다. 추가 변수 `AGENT_EXECUTABLE`은 원본 Python 파일 또는 Linux 실행 파일을 가리킨다. 앱·수동 관제·cron은 같은 환경 파일을 읽는다.

제공된 원본 실행 파일은 PDF와 달리 키 디렉터리 경로 및 `secret.key` 파일명을 요구한다. 원본 설치 시 설치기가 PDF의 `t_secret.key`와 원본의 `secret.key`를 모두 agent-admin:agent-core / 0660으로 준비한다. 실행기는 알려진 원본 파일명에 한해 자식 프로세스의 `AGENT_KEY_PATH`를 키 디렉터리로 변환한다. 기본 환경 파일은 PDF 형식의 파일 경로를 유지한다.

SSH drop-in은 `/etc/ssh/sshd_config.d/00-agent-app.conf`다. Port 20022와 PermitRootLogin no를 기록한 뒤 유효 설정을 검증하며, 충돌 시 관리 파일을 복구한다. 방화벽은 UFW로 통일하고 기존의 다른 사용자 규칙이 있으면 자동 삭제하지 않고 중단한다. VM 콘솔에서 실행하도록 분리했다.

`agent-admin`의 cron은 관제를 매분, 보존 작업을 매일 03:15에 실행한다. 기존 crontab의 다른 항목을 보존하고 프로젝트 태그가 붙은 항목만 교체한다. 방화벽 조회에 필요한 sudo 권한은 인수가 고정된 `ufw status`로 한정한다. 앱 서비스에는 root 권한을 주지 않는다.

## 코드 설명

`monitor.sh`는 `_main()`이 경로·포트·로그 권한을 검사하고 잠금을 얻은 뒤 `_health_check()` → `_check_firewall()` → `_collect_resources()` → `_append_log()`를 실행한다. `_find_pid()`는 같은 사용자 프로세스의 명령 인수를 정확히 비교한다. 같은 이름의 런처가 먼저 발견돼도 해당 앱 후보 중 실제 리스너를 가진 PID를 선택한다. 수집 중 앱이 종료되면 성공 로그를 기록하지 않는다.

CPU는 시스템 전체의 두 누적 tick 표본 차이를 사용한다. 계산식은 `100 × (전체 증가량 - 유휴 증가량) / 전체 증가량`이며 유휴에는 iowait을 포함한다. 메모리는 `100 × (MemTotal - MemAvailable) / MemTotal`, 디스크는 루트 파일시스템 Used%다. 로그의 PID는 앱 PID이고 CPU·MEM은 시스템 전체 수치다.

경고와 장애는 구분한다. 프로세스·포트 오류는 exit 1, 임계값 초과나 방화벽 비활성·조회 불가는 경고 후 계속한다. 로그 회전은 동시 실행 잠금 안에서 새 행의 크기를 합산해 수행하므로 정상적으로 생성한 로그가 쓰기 직후 한도를 초과하지 않는다. 10MiB는 10,485,760바이트, 파일 수는 활성 파일까지 포함한 10개로 정했다.

`report.sh`는 로그를 한 번 읽어 지표 3개의 누적합·최대·최소와 발생 시각을 계산한다. 시각 범위는 양끝을 포함하며 잘못된 실제 달력 날짜와 역전된 기간은 거부한다. 잘못된 형식의 행은 집계하지 않고 일치 표본이 0개이면 안내만 출력한다.

`archive.sh`는 관제와 같은 잠금으로 회전 파일 이동 충돌을 막는다. 7일이 지난 비활성 로그만 압축하고 활성 `monitor.log`·`boot.log`는 보존한다. `.gz`는 압축해 이동한 시점부터 30일 보존한다. 시간 기준 파일 판정은 분 단위 `find -mmin`을 사용한다. 기존 아카이브와 이름이 충돌하면 덮어쓰지 않고 경고한다.

## 실제 검증 결과

`scripts/validate.sh`를 2026-11-25 15:20:55(KST)에 실행해 **19개 검증을 모두 통과**했다. 결과는 `evidence/local-validation.log`에 보존했다. 여기에는 실제 환경·uid, 대체 앱의 부트 출력, 실제 관제 출력·로그와 각 테스트의 PASS가 포함된다. 고정 통계 입력과 방화벽 상태 분기 테스트는 합성 입력을 사용하며 실제 방화벽을 변경하지 않는다.

실제 초기 표본은 15:20:57, 앱 PID 472, CPU 0.0%, MEM 5.4%, 루트 디스크 1%였다. 지원 방화벽이 설치되지 않은 테스트 환경에서 경고를 출력하고 관제를 계속한 것도 확인했다. 이 수치는 해당 시점의 WSL 전체 상태이며 운영 VM 측정값은 아니다.

이 격리 검증은 프로젝트 내부 임시 경로에서 수행했으므로 운영 경로의 권한과 실제 계정별 접근 통제의 증거를 대신하지 않는다. 이후 별도 systemd·보조 그룹 회귀 검증을 수행했고, 사용자의 Mac 배포 결과는 아래에 구분했다.

전달된 원본 설치 출력은 cron 대기 단계에서 끝나며 최종 판정 줄은 포함하지 않는다. 이후 사용자가 이 대화에서 **“원본 앱도 ALL DEPLOYMENT CHECKS PASSED 나왔어”**라고 보고했다. 따라서 최종 통과는 사용자 확인으로 기록하며, 원본의 cron 새 표본 시각·수치나 미수신 최종 출력 줄을 생성해 덧붙이지 않았다. 제출 시 Ubuntu의 `~/4-1/evidence/deployment-evidence-original.txt`를 함께 보관하면 마지막 cron 표본과 최종 성공 메시지까지 확인할 수 있다.

운영 monitor.log에는 교체 전 대체 앱 PID 7260의 표본과 교체 후 원본 PID 10382의 표본이 함께 남아 있다. 원본 실행을 설명할 때는 21:14:08 이후 PID 10382의 기록을 사용한다.

## 최종 제출 전 실서버 증거 체크리스트

- [x] 원본 ZIP에서 x86·ARM64 실행 파일 확인 및 x86 격리 기동 검증
- [x] Mac Ubuntu에 x86 원본 설치·부트·관제 확인, 최종 배포 통과는 사용자 보고로 확인
- [x] `sshd -T`의 Port 20022 / PermitRootLogin no 및 실제 SSH 리스너 확인
- [x] UFW active / 기본 수신 거부 / 허용 TCP 20022·15034 확인

- [x] 대체 앱의 현재 실행에서 부트 5개 [OK] / Agent READY 확인
- [x] 원본 앱의 현재 실행에서 부트 5개 [OK] / Agent READY 확인
